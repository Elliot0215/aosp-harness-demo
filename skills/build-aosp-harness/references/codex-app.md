# Codex App 接入与交付

当目标是 Codex App/GUI 时读取。只说 Codex 且没有既有客户端约定时默认走本流程，并说明选择；显式 CLI 保持 CLI 流程。本参考定义搭建交付标准，不代表任意 App 版本已支持或已验证所有 hooks。

## 1. 确认实际环境

记录源码树绝对路径、App 版本（无法读取则由用户提供）、任务执行主机、操作系统、用户、shell，以及相关项目配置来源。CLI 版本不是 App 内置运行时版本的证据。先检查本地实现与配置，仍不明确时查当前官方资料；可使用已安装的 openai-docs skill，但本 skill 不依赖它必然存在。

Windows App 的本套 Bash 适配使用已配置的 WSL/Linux 执行环境。确认代理与 hooks 能访问同一源码树、工具和状态目录，不假设 Windows 路径、WSL 路径或 CLI 环境自动互通。原生 PowerShell 需要另行适配和验证，不能套用 Bash 配置后标为可用。

区分源码树根、各 Git project 根和外层教学仓。真实 AOSP 选完整源码根，教学示例选 `aosp-harness/codex/`。任务 cwd 必须满足目标 hook 的根目录契约。不要用普通单仓 worktree 替代完整多仓源码树；并行 feature 使用分别准备的完整工作区。

## 2. 落地 App 入口

复用已安装的配置，修改真实源文件，保留普通根指令和无关设置。存在冲突时先形成保留原约束的合并结果，不强制覆盖或通过全局权限设置绕过。

目标 Harness 应包含：

- 安装器：以标准 `.codex`、`.agents/skills` 入口暴露所需配置和 skills；支持重复安装与冲突保护。
- `prepare-feature`：检测 feature、校验涉及仓、准备根上下文，成功后退出；不启动 CLI，不创建或覆盖任务快照。CLI wrapper 共用此步骤。
- 生命周期入口：验证任务 cwd、已准备的上下文、当前 feature 和涉及仓。所有声明支持的 SessionStart 来源及 UserPromptSubmit 通过同一边界；首次 startup 建立基线，已有状态只校验，resume/clear/compact 不补写缺失基线。输入错误或快照缺失、损坏、漂移时按已确认的客户端协议阻断。
- feature 指令：显式路由实际存在的 skills 与验证脚本，并说明切换 feature 后准备并新建任务。

不能在 SessionStart 内切换链接后声称本次任务已加载新指令；启动前准备才是首次上下文选择边界。恢复同 feature 任务需验证原快照，不用当前 feature 覆盖它。旧 CLI 入口保持兼容。

### 模板缺项必须处理

读取当前实现再复用。现有 Codex 模板默认按 UID/session_id 存快照，未按源码树隔离。生成目标时加入规范化物理树根的稳定标识，例如 SHA-256，以“树根标识 + 会话标识”划分状态；由各入口共同推导，App 不依赖 CLI 临时导出的环境变量。状态目录覆盖参数也遵守树隔离契约，保留已有私有权限与拒绝不安全路径的检查。迁移前说明旧快照不能证明新状态有效，要求重新准备并新建任务，不以恢复时自动迁移基线放行旧任务。

检查模式应明确是真实多仓还是离线示例；真实目标不能因 `.repo` 缺失就静默跳过涉及仓检查。沿用目标项目已确认的模式选择，独立 project/worktree 也显式检查。

提示提交检查无法覆盖同一轮中的后续分支变化。记录事件覆盖范围，要求未覆盖的写操作前重新检查；只有核实并实测当前 App 的写工具事件与阻断协议后才能增加这层自动保护。不得将提示提交阻断宣传为所有写操作持续保护。

## 3. 准备并交接到 App

在新任务创建前，从目标树运行安装和准备。交付时用用户的真实绝对路径与实际命令替换示例，不留下未解析占位符：

```bash
cd /实际/AOSP/源码根
bash features/install-harness.sh
./.codex/bin/prepare-feature
```

明确告知 App 中应选择的项目目录和执行环境，并在该目录新建任务。不要启动 CLI 冒充 GUI 接入，也不要把外层仓库当前任务当作目标项目的加载证据。

项目配置及 hook 定义按当前客户端支持方式审查、信任；修改定义后重新确认。官方文档描述的 CLI `/hooks` 不是 App 界面或两者共享信任状态的证明。无法找到 App 支持的信任路径时报告具体缺项；不加 bypass 参数、不自动修改全局信任或权限策略来通过验收。

需要新任务时默认提供下面的提示供用户创建。只有用户明确授权创建任务后，才使用可用的任务管理工具并检查实际 cwd；搭建授权不自动等于创建任务授权。

首条提示根据目标 feature 和 skill 名填写：

```text
请只读验收本项目的 Codex App Harness，不构建、不部署、不访问设备：
1. 报告工作目录、当前 feature，以及本任务已加载的项目指令来源和关键约束。
   区分启动时已加载的指令与之后手动读取的文件。
2. 从本任务可用技能列表确认目标流程 skills 的名称和来源；仅调用以读取流程，
   不执行其中的构建或部署命令。检查是否有同名全局 skill 遮蔽项目版本。
3. 检查当前任务自动触发 hooks 的可见记录及对应原始快照，报告任务标识、
   树根和 feature。不要手动投递 payload、创建快照或修复状态来制造通过证据。
4. 无法确认的项目标为未验证，给出下一步。不要只根据文件存在宣布接入完成。
```

## 4. 两级验收

### 离线：验证生成的目标，而非仅验证模板

在带空格路径的隔离树中执行目标文件和实际配置中的命令；使用模拟客户端，禁止意外启动真实 App/CLI、编译或设备操作。至少覆盖：

| 场景 | 通过条件 |
| --- | --- |
| 安装/重复安装/入口冲突 | 幂等；普通文件和无关配置保留；失败只回滚本次创建内容 |
| App 准备 | 无 CLI 调用；正确选择上下文；缺仓、非法分支与不完整清单阻止准备 |
| 新任务与错误 cwd | 已准备的新任务建立快照；错误目录或未准备上下文阻断 |
| 恢复与重复启动 | 原基线不被覆盖；缺失或损坏快照阻断 |
| feature 与非锚点仓漂移 | 分别检测并阻断；恢复不修补基线 |
| 两树使用同一 session_id | 状态互不覆盖；一树漂移不影响另一树的有效任务 |
| skills 路由 | 路径、名称、构建与验证入口均对应目标，不残留 Demo 参数 |

测试失败须修复目标后重跑；无法修复就保留失败结论。既有模板若暴露缺陷，明确区分模板结果与修正后的隔离目标结果。

### 真实 App：验证发现、执行与阻断

在目标目录的新任务中观察下列行为。漂移和删除快照等故障注入放在可丢弃的完整验收副本中，不能切换用户工作树或删除其活动任务状态。验收副本结果记录对应路径；副本成功不替代实际目标的指令、skills 与配置加载确认。

1. 新任务从正确根目录加载预期 feature 指令；使用可见指令来源或该任务启动记录作证。事后 `cat AGENTS.md` 仅证明文件可读。
2. App/任务可用技能列表发现项目 skills，显式调用后读取正确源文件；同名全局 skill 不遮蔽目标版本。只读取流程，不执行构建。
3. 受信任 hook 在该任务自动执行，产生对应树根和 session 的快照。保留可关联的事件/运行记录；旧快照或手动执行脚本不算证据。
4. 同 feature 恢复并发送只读请求可继续；切换有效 feature 或让非锚点涉及仓漂移后，自动 hook 在代理继续工作前阻断。仅代理读到指令后自行决定停止不算自动阻断。
5. 缺失快照后恢复被阻断，不自动重建；准备新 feature 后，新任务可正常工作。clear/compact 等已声明支持但无法实际触发的事件单列未验证，不冒充实测通过。

App 不派发必要事件、无法审查信任、skills 不可发现，或证据无法关联到目标任务时，继续排查可解决项；仍受外部条件阻塞则交付准确的未完成说明。不得改成“手动检查可用”而宣布完整接入完成。

## 5. 交付记录与结论

在目标 feature 现有文档中补充使用与验收；没有合适位置时创建简短的 `APP-USAGE.md` 和 `APP-ACCEPTANCE.md`。记录：源码根、feature、执行环境、App 版本、任务标识、配置/skill 来源与测试时版本或哈希、各项结果和原始证据路径。日志只保留必要运行信息，不复制无关聊天或凭据。

使用说明包含安装/准备命令、App 项目选择、首条提示、正常恢复、切换 feature 和故障恢复。验收记录分开列出离线、App 集成、Android 编译及设备验收，未执行项明确标记。

只有上下文加载、skills 发现与调用、正常恢复及自动漂移阻断等必需项全部有实际 App 证据，才写“Codex App 接入完成”。必要证据缺失时写“App 接入未完成”，列出阻塞项、用户需完成的具体操作及重验步骤；离线通过与否另行报告。App 接入完成也不意味着 Android 功能已实现、编译通过或真机通过。

官方契约需结合当前版本核对：[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[skills](https://learn.chatgpt.com/docs/build-skills)、[hooks](https://learn.chatgpt.com/docs/hooks)。
